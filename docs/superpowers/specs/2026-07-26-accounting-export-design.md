# Бухгалтерия: копирование таблицы ручных работ — дизайн

**Дата:** 2026-07-26  
**Статус:** утверждён к реализации (согласовано с Наталией)  
**Область:** «Ввод данных» + «Отчёт за период». Демо и прод — один код.  
**Контекст:** после разбивки к-во чел. по виду/кварталу. Образец колонок — Excel «Уход 2026г+ Допосадка» хозяйства (скрин 2026-07-26).  
**Архитектура MVP:** API отдаёт готовый текст (TSV) → клиент «Скопировать» / «Поделиться». Отдельной вкладки «Бухгалтерия» нет.

## 1. Зачем

Бухгалтеру нужна таблица в формате их Excel: строки ручных работ с датой, бригадой, к-во чел., фактом; колонки нормы/расценки/оплат — пустые, их заполняет бухгалтер.

Бригадиры часто на телефоне: **скачивание `.xlsx` нежелательно** (память, не умеют удалять). Почту подключим **после** договорённости с бухгалтером (фиксированный адрес). Сейчас — как у агронома на «Выполнении»: **скопировать текст** (+ «Поделиться», где браузер умеет).

Механизированные работы в бухгалтерию **не идут** (агроному — га на «Выполнении», уже есть).

## 2. Что меняем / что не трогаем

### Меняем

1. API `GET /api/accounting/export` — строки ручных работ за день или период + явка/разбивка для к-во чел.
2. Кнопки «Скопировать» и «Поделиться» на **Вводе** (у «Всего за день») и на **Отчёте** (у результата периода).
3. Чистая сборка TSV (серверный модуль + тесты): колонки как в шаблоне бухгалтера.

### Не меняем в этой задаче

- Вкладка «Бухгалтерия».
- Скачивание `.xlsx`, SMTP/почта, MAX-бот.
- Заполнение нормы, расценки, оплаты людям, транспорта, бригадирских, суммы итого.
- Механизированные логи в выгрузке.
- Реальный сорт / год посадки из inventory (в демке — заглушки; в проде до inventory — тоже безопасные заглушки или пусто — см. §4).
- Редактирование шапки Excel («ООО …», периоды подвязки и т.п.) — вне MVP; копируем только таблицу строк + заголовок колонок.

## 3. Поведение UI

### Ввод данных

- Рядом с блоком «Всего за день» (акцент на ручных работах):  
  - **Скопировать** — TSV за **дату ввода** в буфер.  
  - **Поделиться** — тот же текст через `navigator.share({ text })`, если доступно; иначе кнопка скрыта или disabled.
- Успех: коротко «✓ Скопировано» (как на «Выполнении»).
- Пусто (нет ручных за день): «Нет ручных работ за эту дату» — в буфер не пишем.

### Отчёт за период

- У результата отчёта те же две кнопки.
- Выгрузка за **весь выбранный период** (`from`–`to`): все ручные строки; колонка «Дата» на каждой строке (для сверки с бухгалтером).
- Пустой период — то же сообщение.

### Формат текста (аналог листов)

В настоящем Excel позже: **1 фамилия бригады = 1 лист**.  
В TSV MVP: блоки с маркером листа, затем общая строка заголовков колонок (один раз) или заголовок в каждом блоке — **выбор реализации: заголовок колонок один раз в начале файла, затем блоки:**

```text
--- Панова ---
<заголовок колонок>
<строки>
--- Иванов ---
<заголовок колонок>
<строки>
```

Разделитель колонок — Tab (`\t`), строки — `\n`. Вставка в Excel раскладывает по ячейкам. Маркер `--- Фамилия ---` бухгалтер видит как служебную строку (можно удалить вручную) или оставить как разделитель; при переходе на `.xlsx` станет именем листа.

## 4. Колонки (как в шаблоне)

Порядок и названия — по образцу Excel. Пустые ячейки — пустая строка между табами.

| # | Колонка | Кто | Правило MVP |
|---|---|---|---|
| 1 | Технологическая операция, Условное обозначение | мы | `work_type` |
| 2 | год посадки | мы | демка/пока нет inventory: заглушка (напр. `2020`); позже из inventory по кварталу/клетке |
| 3 | квартал | мы | `quarter`; нет — пусто |
| 4 | сорт | мы | демка: заглушка (напр. `Ркацители`); позже из inventory |
| 5 | Услуга (работа) | мы | **название предприятия**; в демку из данных не берём — константа-фейк, напр. `ООО «Демо-Агро»`; в проде — из `BRAND_NAME` / конфига клиента |
| 6 | Дата | мы | `YYYY-MM-DD` или `DD.MM.YYYY` как в образце — **в реализации `DD.MM.YYYY`** |
| 7 | к-во чел. | мы | как на плашке «Ручные работы»: кусок `people_allocations` (сотрудник + вид + квартал); нет куска → `attendance.people_count`; нет числа → пусто |
| 8 | Бригада | мы | фамилия работника (`employee`) |
| 9 | Факт | мы | число: кусты (`rows_bushes` / кусты) или часы (`hours`); без единиц в ячейке (как «1452» в образце). Режим только рядов без кустов — число рядов (факт в их учёте) |
| 10 | Норма | пусто | бухгалтер |
| 11 | Расценка | пусто | бухгалтер |
| 12 | оплата людям | пусто | бухгалтер |
| 13 | транспорт 150;450/чел. | пусто | бухгалтер |
| 14 | Бригадирские 150/чел. | пусто | бухгалтер |
| 15 | Сумма итого | пусто | бухгалтер |

Заголовок TSV — точные подписи колонок 1–15 (как в таблице выше / близко к шаблону).

## 5. Откуда строки (агрегация)

Источник смысла — блок **«Ручные работы»** в «Всего за день» / отчёте за период (не механизированные).

Одна строка выгрузки = одна агрегированная линия плашки:

- ключ группировки как у `groupManualLogs` / линий отчёта: работник + вид работ + квартал (+ клетка и режим, если плашка их разделяет);
- **Факт** — то же число, что уходит в текст плашки для кустов или часов;
- если на плашке две линии (обрезка 7 чел. и хозработы 1 чел.) — в TSV **две строки**.

Не дублировать «сырые» карточки записей сверху, если плашка уже схлопнула их — брать уровень плашки.

К-во чел.: переиспользовать логику `resolvePeopleCountForLine` (сервер + те же правила, что UI после фикса разбивки).

## 6. API

Владение — как у логов / явки (`demo_session_id` / `brigadier_id`).

| Метод | Назначение |
|---|---|
| `GET /api/accounting/export?date=YYYY-MM-DD` | День (Ввод) |
| `GET /api/accounting/export?from=YYYY-MM-DD&to=YYYY-MM-DD` | Период (Отчёт) |

Правила:

- Задан либо `date`, либо пара `from`+`to` (включительно). Иначе 400.
- Только ручные виды (`kind !== mechanized`).
- Ответ JSON: `{ text: string, sheetNames: string[], rowCount: number }`  
  - `text` — готовый TSV для буфера;  
  - `sheetNames` — список фамилий-листов (удобно для UI/отладки);  
  - `rowCount` — число строк данных (без заголовков и маркеров).
- Пустой результат: 200 + `text: ''`, `rowCount: 0` (клиент показывает сообщение).

Чистая логика (без HTTP) — модуль вроде `server/accountingExport.js`: вход логи + present + allocations + stubs → `{ text, sheetNames, rowCount }`. Тесты node:test.

## 7. Ошибки и крайние случаи

| Ситуация | Поведение |
|---|---|
| Нет ручных работ | `rowCount: 0`; UI не копирует, показывает сообщение |
| Нет Web Share API | «Поделиться» скрыта; «Скопировать» работает |
| Офлайн | Как остальные GET отчёта: если нет сети — сообщение об ошибке; отдельный офлайн-кеш выгрузки не делаем |
| Несколько фамилий | Несколько блоков/листов; порядок фамилий — locale `ru` |
| Куски разбивки без совпадения строки | к-во чел. пусто или N явки по правилу §4 п.7 |
| Часы без квартала | квартал пустой; кусок с пустым кварталом матчится |

## 8. Критерии готовности

- [ ] Ввод: копируется TSV за дату ввода; содержимое совпадает с ручной плашкой «Всего за день» по составу строк и к-во чел.
- [ ] Отчёт: копируется весь период; у каждой строки своя дата.
- [ ] Только ручные; механизированных строк нет.
- [ ] Колонки 10–15 пустые; 1–9 заполнены по §4.
- [ ] Несколько фамилий → несколько блоков `--- Фамилия ---`.
- [ ] «Поделиться» на поддерживающем браузере отдаёт тот же текст; на неподдерживающем не ломает экран.
- [ ] Пустой день/период — понятное сообщение, без «пустого успеха».
- [ ] Демо и прод одинаково по API/UI; фейк предприятия/сорта/года — только там, где нет реальных данных.

## 9. Вне скоупа (следующие задачи)

- Отправка на почту бухгалтера (фиксированный адрес из `.env` / настроек) с вложением `.xlsx`.
- Настоящий `.xlsx`: 1 фамилия = 1 лист листа книги.
- Год посадки и сорт из `inventory.json`.
- Автоподстановка транспортных / бригадирских (150×чел. и т.п.) — только если бухгалтер так решит; сейчас пусто.
- Шапка файла (юрлица, периоды операций) как в полном Excel-шаблоне.
