# Единые плашки отчётов «Всего за день» и «Отчёт за период» — дизайн

**Дата:** 2026-07-20  
**Статус:** утверждён к реализации (согласовано с Наталией)  
**Область:** фронт (`public/js/app.js`, `public/styles.css`). Сервер/БД не трогаем. Демо и прод — один код рендера.

## 1. Зачем

На вкладке «Ввод данных» блок **«Всего за день»** сейчас — плоский список по клеткам, без разделения ручных и механизированных работ. **«Отчёт за период»** уже почти в нужном виде (два блока), но эмодзи культур общие (🌳/🍓), а дневной отчёт с периодом расходятся.

Нужен **один визуальный формат** для обоих отчётов: плашки ручные / техника, внутри — по виду работ или трактористу, с понятными эмодзи культур.

## 2. Что показываем

Оба отчёта строятся **одним рендерером** (переиспользуем/обобщаем `renderTwoBlocksReportHtml` и связанные helpers).

```
🛠 Ручные работы
  ┌ Обрезка · 🍇 Виноград
  │   Иванов — 5 рядов, 685 кустов · Кв.1, клет.1
  │   Петров — 3 ряда, 410 кустов · Кв.1, клет.2
  └ Прополка · 🍎 Яблоня
      Сидоров — 2 ряда · Кв.2, клет.1

🚜 Механизированные работы
  ┌ Иванов
  │   Опрыскивание · 🍇 Виноград · Кв.2 — 5 га
  └ Петров
      Вспашка · 🍎 Яблоня · Кв.1 — 3.5 га

Всего за день/период: руками — …; техникой — ….
```

- Пустой блок (нет ручных или нет техники) — **не рендерим**.
- Заголовок итогов: на дневном — «Всего за день», на периоде — «Всего за период» (одна функция с параметром подписи).
- Разделение manual / mechanized — по `work_types.kind` через уже существующий `kindOfWorkType`.

### Ручные

- Внешняя плашка: **вид работ + культура** (в демо `estate_id` = культура; в проде — если culture/estate есть в логе).
- Внутри строки: **работник — мера · место** (Кв./клет.).
- Меры как сейчас: ряды / ряды+кусты / часы.

### Механизированные

- Внешняя плашка: **тракторист** (работник).
- Внутри строки: **вид работ · культура · место — мера** (га / км / часы).

## 3. Эмодзи культур (конкретные)

Обновить `cultureEmoji(name)` — по подстроке названия (регистр не важен):

| Культура (фрагмент) | Эмодзи |
|---------------------|--------|
| виноград | 🍇 |
| яблон | 🍎 |
| груш | 🍐 |

| клубник | 🍓 |
| вишн / черешн | 🍒 |
| персик / абрикос | 🍑 |
| слив / алыч | 🟣 |
| орех | 🥜 |
| смородин / ежевик / голубик / жимолост | 🫐 |

Заголовки блоков: **🛠 Ручные работы**, **🚜 Механизированные работы** (как сейчас в периоде).

## 4. Что не меняем

- Блок **«Записи за дату»** с кнопкой ✕ — остаётся отдельным списком для удаления.
- Контроль рядов, спорные, API логов, сиды демо.
- Логика агрегации цифр (`rowWeightSum`, totals) — без изменения формул, только группировка/HTML.

## 5. Технический план (кратко)

1. Расширить `cultureEmoji` конкретным словарём.
2. Вынести единый `renderPlatesReportHtml(logs, { grandLabel })` на базе `renderTwoBlocksReportHtml` / `renderManualBlockHtml` / `renderMechBlockHtml`.
3. `renderDailyTotalsHtml()` → вызов единого рендерера с `this.entries` и подписью «Всего за день».
4. `getReport()` (период) → тот же рендерер с «Всего за период» (и в демо, и в проде — один вид).
5. При необходимости слегка подправить CSS `.report-block` / `.report-group`, чтобы дневной блок `#i2-totals` выглядел так же, как `#report-result`.

## 6. Критерий готовности

- После добавления записи на «Ввод данных» в «Всего за день» видны две верхние плашки (если есть оба типа работ), внутри — как в §2.
- «Отчёт за период» визуально совпадает по структуре с дневным.
- Виноград/яблоня/груша/малина дают разные эмодзи из таблицы §3.
- Удаление записи из «Записи за дату» по-прежнему работает; сводка обновляется.
