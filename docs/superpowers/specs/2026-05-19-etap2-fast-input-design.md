# Дизайн Этапа 2: Быстрый структурированный ввод

**Дата:** 2026-05-19
**Статус:** одобрен, готов к плану реализации

## Контекст

Сейчас бригадир вводит работу одним текстовым полем — печатает фамилии,
кварталы, клетки и ряды строками. Это медленно и легко ошибиться (особенно
в фамилиях). Этап 2 заменяет текстовый ввод **структурированным**: бригадир
выбирает из списков, печатать фамилии и форматировать строки не нужно.

Этап 2 строится поверх Этапа 1 (аккаунты, вход по паролю, изоляция данных).
Каждый бригадир работает только со своими данными.

## Что меняется

- Текстовое поле ввода и кнопка «Обработать» **убираются**. Вкладка «Ввод
  данных» становится экраном структурированного ввода.
- Появляются три серверных списка: сотрудники (личные у бригадира), виды
  работ (общие для всех), явка (личная, на каждый день своя).
- В каждую запись добавляется **вид работ** и **режим подсчёта**.
- В журнал и отчёт за период добавляется разбивка по виду работ.

## Списки

### Сотрудники — личный список бригадира
- У каждого бригадира свой список сотрудников. Сотрудник = только фамилия,
  больше ничего.
- Бригадир сам добавляет и удаляет сотрудников.
- Это полная бригада — обычно 15-30 человек.
- Удаление сотрудника не трогает прошлые записи журнала: в каждой записи
  фамилия хранится как текст в самой строке, а не ссылкой.

### Виды работ — общий список
- Один общий список названий видов работ, одинаковый для всех бригад.
- Поставляется с набором основных: обрезка, подвязка, опрыскивание, уборка
  территории, подготовка саженцев.
- Любой бригадир может добавить новый вид работ — он становится доступен
  всем.
- Вид работ — это только название, никаких настроек у него нет.

### Явка — «кто сегодня на работе»
- На каждый день у бригадира свой список присутствующих.
- Утром список пустой. Бригадир отмечает, кто вышел, выбирая из полного
  списка сотрудников.
- Отмеченные — «на работе сегодня», обычно 8-12 человек.
- Опоздавшего можно доотметить в любой момент дня.
- Назавтра список явки снова пустой — отмечается заново.

## Экран ввода

Заменяет вкладку «Ввод данных». Сверху вниз — четыре блока.

### Блок 1. Контекст
Хозяйство → Квартал → Клетка → Вид работ → Как считать. Контекст «держится»:
выбранное остаётся, пока бригадир сам не сменит. Под одним контекстом можно
записать сколько угодно сотрудников, не выбирая его заново.

- **Хозяйство** — как сейчас (Жемчужина / Наш Крым), запоминается на
  устройстве (`localStorage`).
- **Квартал, Клетка** — выпадающие списки из инвентаризации (как сейчас).
- **Вид работ** — выпадающий список из общего списка видов работ; рядом
  «+ новый» для добавления нового вида работ.
- **Как считать** — переключатель из трёх режимов (см. ниже). Выбирается
  отдельно, к виду работ **не привязан**.

### Режимы подсчёта
- **Ряды + кусты** — бригадир вводит ряды; количество кустов считается из
  инвентаризации. Большинство работ.
- **Только ряды** — бригадир вводит ряды; кусты не считаются.
- **Только часы** — бригадир вводит часы; ряды не нужны.

Для режима «только часы» квартал и клетка необязательны (уборка территории
не привязана к клетке). Для режимов с рядами клетка обязательна — ряды
принадлежат клетке.

### Блок 2. Сегодня на работе
- Кнопка-список «Выбрать рабочих из бригады» раскрывает полный список
  сотрудников (с прокруткой). Бригадир отмечает присутствующих. В этом же
  списке — «+ добавить нового»: новый сотрудник заносится в полный список и
  сразу отмечается присутствующим.
- Ниже — отмеченные сотрудники плашками. В плашках только присутствующие
  сегодня (8-12), экран не перегружен.
- Тык по плашке выбирает сотрудника для ввода записи.

### Блок 3. Добавить запись
- Сотрудник — выбранный плашкой из блока 2.
- Поле измерения зависит от режима подсчёта:
  - «Ряды» — для режимов «ряды + кусты» и «только ряды». Одно поле, формат
    «1-5, 9, 11, 15»: номера через запятую, диапазон через тире.
  - «Часы» — для режима «только часы». Число.
- Кнопка «Добавить» создаёт запись и кладёт её карточкой в блок 4. Контекст
  и явка остаются; поле сотрудника и измерения очищается под следующего.

### Блок 4. Записи за сегодня
- Карточки записей, добавленных за день.
- Карточка показывает фамилию, хозяйство/квартал/клетку, вид работ и
  измерение по режиму:
  - Ряды + кусты: «ряды 1-5 · 5 рядов · 145 кустов».
  - Только ряды: «ряды 1-5 · 5 рядов».
  - Только часы: «4 часа».
- У каждой карточки кнопка «удалить» — убирает запись (как в журнале).

## Один сотрудник — несколько записей в день

Сотрудник за день может работать на разных кварталах, клетках или видах
работ. Тогда он появляется в нескольких записях за день — это нормально.
Каждая запись отдельная и независимая (например: Иванов с утра обрезка на
клетке 2, потом уборка территории — две записи с одной фамилией).

## Модель данных

### Таблица `work_logs` — добавляются колонки
- `work_type TEXT` — название вида работ.
- `measure_mode TEXT` — режим подсчёта: `rows_bushes` / `rows_only` / `hours`.
- `hours NUMERIC` — часы (для режима `hours`); иначе пусто.
- `rows` — номера рядов «1,2,3,…» (как сейчас); для режима `hours` пусто.
- `bushes` — кусты; заполняется только для `rows_bushes`, иначе 0.
- `quarter`, `cell` — становятся необязательными (для режима `hours` пусты).
- Существующие записи при миграции: `measure_mode` = `rows_bushes`,
  `work_type` пусто.

### Таблица `employees` (новая) — личный список сотрудников
| Поле | Тип | Описание |
|---|---|---|
| id | SERIAL PRIMARY KEY | |
| brigadier_id | INTEGER NOT NULL | ссылка на `brigadiers(id)` |
| name | TEXT NOT NULL | фамилия |
| created_at | TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP | |

### Таблица `work_types` (новая) — общий список видов работ
| Поле | Тип |
|---|---|
| id | SERIAL PRIMARY KEY |
| name | TEXT UNIQUE NOT NULL |
| created_at | TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP |
Заполняется основными видами работ при первом запуске сервера, если пустая.

### Таблица `attendance` (новая) — явка
| Поле | Тип |
|---|---|
| brigadier_id | INTEGER NOT NULL |
| date | TEXT NOT NULL (YYYY-MM-DD) |
| employee_id | INTEGER NOT NULL — ссылка на `employees(id)` |
Одна строка — один присутствующий сотрудник в этот день у этого бригадира.
PRIMARY KEY (`brigadier_id`, `date`, `employee_id`). Отметить явку — вставить
строку; снять — удалить.

## Endpoints

Все требуют входа (как в Этапе 1). Сотрудники и явка изолированы по
бригадиру; виды работ — общие.

- `GET /api/employees` — список сотрудников вошедшего бригадира.
- `POST /api/employees` `{name}` — добавить сотрудника.
- `DELETE /api/employees/:id` — удалить сотрудника (только своего).
- `GET /api/work-types` — общий список видов работ.
- `POST /api/work-types` `{name}` — добавить вид работ (если такого ещё нет).
- `GET /api/attendance?date=` — присутствующие на эту дату.
- `POST /api/attendance` `{date, employee_id}` — отметить присутствие.
- `DELETE /api/attendance` `{date, employee_id}` — снять отметку.
- `POST /api/logs` `{date, estate, quarter, cell, work_type, measure_mode,
  employee, rows, hours}` — создать одну запись. Для режимов с рядами сервер
  раскрывает «1-5, 9» в номера рядов; для `rows_bushes` считает кусты из
  инвентаризации.
- `GET /api/logs`, `DELETE /api/logs/:id` — как в Этапе 1, изолированы по
  бригадиру; в выдачу `GET /api/logs` добавляются `work_type`, `measure_mode`,
  `hours`.

Старый `POST /api/process` и текстовый разбор экраном ввода больше не
используются. Логику раскрытия диапазонов рядов и подсчёта кустов из
инвентаризации (`parser.js`: `parseRows`, `getBushesCount`) переиспользуем —
разбор строгого текстового формата не нужен.

## Отчёт и журнал

### Журнал (за день)
- Карточки показывают фамилию, квартал/клетку, вид работ и измерение по
  режиму — так же, как карточки на экране ввода.
- Удаление записи — как сейчас.

### Отчёт за период
- Группировка: сотрудник → вид работ → квартал/клетка.
- Суммы считаются раздельно по единице измерения:
  - записи `rows_bushes` — итог в рядах и кустах;
  - `rows_only` — итог в рядах;
  - `hours` — итог в часах.
- Часы, ряды и кусты между собой не складываются — каждая единица отдельной
  строкой.

## Обработка ошибок

- Ряды: пустое поле или неразобранный формат — «Укажи ряды, например: 1-5, 9, 11».
- Часы: не число или ≤ 0 — «Укажи часы числом».
- Режим с рядами, но не выбрана клетка — «Выбери клетку».
- Не выбран сотрудник — «Выбери сотрудника».
- Не выбран вид работ — «Выбери вид работ».
- Добавление сотрудника или вида работ с пустым именем — отклоняется.
- Добавление вида работ, который уже есть — второй не создаётся, сообщение
  «Такой вид работ уже есть».

## Безопасность (репозиторий публичный)

- Список сотрудников и записи журнала хранятся только в базе данных, не в
  коде. Фамилии в репозиторий не попадают.
- Сотрудники и явка изолированы по бригадиру (правила Этапа 1 сохраняются).
- Названия основных видов работ (обрезка, подвязка и т. п.) — обычные
  агрономические операции, не бизнес-секрет; их допустимо иметь в коде как
  стартовый набор.

## Вне объёма (YAGNI)

- Уборка винограда по вёдрам (вёдра × вес ведра) — вес ведра каждый день
  разный, в расчёт не берём.
- Гектары как единица измерения — три режима (ряды+кусты / только ряды /
  только часы) задачу закрывают.
- Редактирование уже добавленной записи — только удалить и добавить заново.
- Привязка режима подсчёта к виду работ — режим выбирается каждый раз.
- Удаление и переименование видов работ — пока не нужно (общий список,
  чистка при необходимости — отдельно).
- Голосовой ввод — остаётся отложенным с Этапа 1.

## Тестирование

- Тест-фреймворка в проекте нет — не добавляем (не ломаем стиль проекта).
- Сервер: `node --check` на синтаксис; ручная проверка endpoint'ов.
- Ключевые ручные проверки: добавить сотрудника; отметить явку; ввести запись
  в каждом из трёх режимов; проверить карточки и подсчёт кустов; проверить
  отчёт с разбивкой по видам работ; проверить изоляцию — сотрудники и записи
  одного бригадира не видны другому.
- Клиент: ручная проверка на телефоне и в браузере.
