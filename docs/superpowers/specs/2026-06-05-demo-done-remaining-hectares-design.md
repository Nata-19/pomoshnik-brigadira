# Демо-отчёт «Сделано / Осталось в гектарах» — дизайн

**Дата:** 2026-06-05
**Статус:** утверждён к реализации (реализуем ПОСЛЕ Фазы 3 контроля рядов)
**Область:** только демо (`demo-five-modes`), боевого не касается.

## 1. Зачем

Бригадиру нужно видеть прогресс по саду в **гектарах**: сколько площади уже обработано по каждому виду работ и сколько осталось. Ввод данных остаётся как сейчас — **в рядах**. Этот отчёт лишь переводит накопленные ряды в гектары и показывает остаток до полной площади.

Это **новый экран поверх существующего ввода**, НЕ новый режим ввода (Вариант А из брейншторма).

## 2. Что показываем

Отдельная **вкладка «Выполнение»** рядом с Журнал / Отчёт / Спорные / Сверка.

Строки в разрезе **вид работ × квартал**, **сгруппированные по культуре** (в демо «хозяйство» = культура). Показываем ВСЕ культуры сессии сразу, каждая — со своей подписью-заголовком:

```
🌱 Яблоня
   Обрезка · Кв.2 · ряды           Сделано 4.20 га · Осталось 1.80 га
   Полив   · Кв.2 · ряды           Сделано 6.00 га · Осталось 0.00 га
   Вспашка · Кв.2 · механизировано Сделано 5.00 га · Осталось 2.50 га
🌱 Виноград
   Обрезка · Кв.7 · ряды           Сделано 1.10 га · Осталось 6.90 га
```

Две цифры на строку: **Сделано** и **Осталось**. Третьей колонки «спорно» нет.

**Два типа плашек (раздельно, не смешиваем):**
- **ручные** (`rows_bushes`/`rows_only`) — площадь считается из записанных рядов (ряды→га);
- **механизированные** (`hectares`) — площадь введена бригадиром напрямую в гектарах; «сделано» = сумма этих гектаров.
Один и тот же вид работ × квартал, если вдруг записан и рядами, и гектарами, даёт ДВЕ отдельные плашки (с пометкой типа). Режимы `hours` (часы) и `kilometers` (км) площади не дают и в отчёт не попадают.

**Фильтры (множественный выбор):** бригадир отмечает несколько кварталов и несколько видов работ; по умолчанию выбрано всё. Фильтрация — на клиенте, мгновенно, без повторного запроса. (Культура отдельным фильтром не выводится — кварталы в демо нумеруются сквозно и однозначно привязаны к культуре; группировка по культуре делается заголовками.)

## 3. Правила расчёта

Всё считается на **сервере** (там живут парсер и инвентарь).

Каждая строка отчёта имеет **тип (`kind`)**: `manual` (ряды) или `mech` (гектары). Тип берётся из `measure_mode`: `hectares` → `mech`, иначе (`rows_bushes`/`rows_only`) → `manual`. Группировка идёт по `(культура, вид работ, квартал, тип)` — ручные и механизированные считаются и показываются раздельно.

**Сделано (га) — РУЧНЫЕ (`kind=manual`, ряды)** для тройки «культура × вид работ × квартал»:
- Берём записи `work_logs` демо-сессии с `measure_mode IN ('rows_bushes','rows_only')` и непустым `rows` по этому `work_type`+`quarter` (накопительно — **за всё время**, дата не фильтруется).
- Внутри каждой клетки собираем **объединение** номеров рядов из всех записей (любые даты, любые рабочие) и **дедуплицируем** — один ряд засчитывается один раз, даже если его делили между рабочими или писали в разные дни.
- Переводим уникальные ряды клетки в гектары через `parser.getHectaresForRows(estate, quarter, cell, uniqueRows)` (`parser.js:331`, = `uniqueRows.length / totalRows клетки × hectares клетки`).
- Сумма по всем клеткам квартала = «сделано» для этого вида работ в этом квартале, округление до 2 знаков.

**Сделано (га) — МЕХАНИЗИРОВАННЫЕ (`kind=mech`, гектары):**
- Берём записи `work_logs` с `measure_mode='hectares'` по этому `work_type`+`quarter` (у них `rows` пустые, площадь — в колонке `hectares`).
- «Сделано» = **сумма колонки `hectares`** этих записей (накопительно), округление до 2 знаков. Перевод рядов не нужен.

**Всего по кварталу (га):** сумма `hectares` всех клеток квартала из инвентаря (`getDemoInventory`). Это знаменатель — каждый вид работ должен покрыть всю площадь квартала. Клетки с `hectares = null` пропускаются (площадь неизвестна, перевести нельзя) — см. §5.

**Осталось (га)** = `Всего по кварталу − Сделано` для данного вида работ, не меньше 0, округление до 2 знаков.

**Спорные ряды считаются НЕ сделанными:** они лежат в `disputed_rows`, а не в `work_logs`, поэтому в «сделано» не попадают автоматически и остаются в «осталось». Как разберёшь спорный (он ложится в `work_logs` на сегодня) — площадь сама переедет из «осталось» в «сделано». Двойного счёта нет.

**Какие записи попадают в отчёт:** «площадные» —
- ручные `rows_bushes`/`rows_only` с непустыми `rows` (→ `manual`);
- механизированные `hectares` с заполненной колонкой `hectares` (→ `mech`).
Режимы `hours` (часы) и `kilometers` (км, напр. «Перегон трактора») площади не дают и в отчёт НЕ попадают.

## 4. Архитектура

**Сервер — новый endpoint `GET /api/report/hectares`** (demo-aware, `authOrDemo`):
1. Грузим инвентарь: `const parser = new DataParser(await demo.getDemoInventory(pool, req.demo_session_id))` (в боевом — глобальный `parser`; endpoint демо-only, но пишем по существующему паттерну DEMO_MODE).
2. Тянем «площадные» `work_logs` сессии: `SELECT estate_id, quarter, cell, work_type, rows, measure_mode, hectares FROM work_logs WHERE demo_session_id=$1 AND ((measure_mode IN ('rows_bushes','rows_only') AND rows IS NOT NULL AND rows <> '') OR (measure_mode='hectares' AND hectares IS NOT NULL))`.
3. Группируем по `(тип, культура, вид работ, квартал)`: для `manual` — по клеткам множество уникальных рядов (`Set`, CSV `String(rows||'').split(',').map(s=>s.trim()).filter(Boolean)`); для `mech` — сумма колонки `hectares`.
4. Считаем «сделано» по §3 (ручные — через `getHectaresForRows` по клеткам; механизированные — сумма `hectares`), «всего по кварталу» из инвентаря, «осталось» = max(0, всего − сделано).
5. Возвращаем JSON-массив строк (каждая с `estate` и `kind`):
```json
{
  "rows": [
    { "estate": "Яблоня", "work_type": "Обрезка", "quarter": "2", "kind": "manual", "done_ha": 4.20, "total_ha": 6.00, "remaining_ha": 1.80 },
    { "estate": "Яблоня", "work_type": "Вспашка", "quarter": "2", "kind": "mech", "done_ha": 5.00, "total_ha": 7.50, "remaining_ha": 2.50 }
  ]
}
```
Пустой результат → `{ "rows": [] }`.

**Клиент — новая вкладка** в `public/js/app.js` + кнопка вкладки в разметке:
- Метод `loadHectares()` — `GET /api/report/hectares`, сохраняет строки в `this.hectaresRows`.
- Рендер **с группировкой по культуре** (заголовок на культуру), внутри — плашки (стиль `log-group`); каждая плашка помечена типом: «ряды» (`manual`) / «механизировано» (`mech`).
- Чипы-фильтры: уникальные кварталы и виды работ из ответа, множественный выбор, по умолчанию все отмечены; перерисовка по изменению. Культура отдельным фильтром не выводится.
- Если данных нет — дружелюбная заглушка («Пока ничего не записано — заполни журнал, и тут появятся гектары»).

Расчёта на клиенте нет — только отрисовка и фильтрация уже посчитанных строк.

## 5. Ошибки и крайние случаи

- **Клетка без `hectares` (null):** перевести в гектары нельзя. Такая клетка не входит ни в «сделано», ни в «всего по кварталу» (пропускается). Если у квартала вообще нет клеток с площадью — строка по этому кварталу не выводится (нечего показывать). Демо-сид заполняет `hectares`, так что это защита от грязных данных, не нормальный путь.
- **`getHectaresForRows` бросает исключение** (нет клетки/квартала в инвентаре, 0 рядов): клетку пропускаем, остальные считаем; endpoint не падает целиком (try/catch вокруг клетки, как в `POST /api/logs` строки ~1197).
- **Ряд в `work_logs`, которого нет в инвентаре клетки:** `getHectaresForRows` считает по `rows.length`, не проверяя принадлежность; это поведение существующего пересчёта — оставляем как есть (на демо-сиде ряды согласованы).
- **Пустая сессия / нет культур:** `getDemoInventory` вернёт `{estates:{}}`, `work_logs` пуст → `{rows:[]}` → заглушка на клиенте.
- **Осталось < 0** (теоретически, если рядов записано больше, чем в инвентаре): зажимаем в 0.

Чистое ядро уже есть (`getHectaresForRows` покрыта). Новое:
- **Юнит-тест агрегатора** (вынести логику группировки/дедупликации/суммирования в чистую функцию, напр. `server/hectaresReport.js`, чтобы тестировать без БД): на входе массив записей + функция перевода, на выходе строки `{work_type, quarter, done_ha, total_ha, remaining_ha}`. - Прогон `node --test` и `node --check` перед коммитом.

## 7. Что НЕ делаем (YAGNI / отложено)

- Разбивка по клеткам внутри квартала (только вид работ × квартал; клетки можно добавить раскрытием позже).
- Отчёт за период (только накопительно).
- Колонка «спорно» третьей цифрой.
- (ВКЛЮЧЕНО по решению Натали 2026-06-07: механизированные записи `hectares` теперь в отчёте отдельной плашкой — см. §2/§3. `hours`/`kilometers` по-прежнему не входят — это не площадь.)
- **Закрепление кварталов за бригадирами** — это для версии под предприятие (каждый бригадир видит только свои гектары), фиксируется отдельно, не в этой демо-фиче.
- **Парковка:** расчёт по тракторам / солярке / для бухгалтеров — отдельное обсуждение позже.
