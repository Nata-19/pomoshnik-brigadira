# Дизайн: голосовой ввод через Web Speech API

**Дата:** 2026-05-18
**Статус:** одобрен, готов к плану реализации

## Контекст и проблема

Сейчас голосовой ввод работает по схеме: запись аудио в браузере
(`MediaRecorder`) → отправка blob на сервер `POST /api/transcribe` →
сервер проксирует в Hugging Face Whisper API → текст возвращается в браузер.

Проблемы этой схемы:
- Hugging Face нестабилен и блокируется по IP в сети разработчика.
- Бесплатный лимит сторонних STT-API (SaluteSpeech 100 мин/мес и т.п.)
  привязан к одному аккаунту и не масштабируется на 10-15 бригадиров.
- Сервер вынужден принимать и пересылать аудио (нагрузка, секрет `HF_TOKEN`).

## Решение

Распознавать речь прямо в браузере через Web Speech API
(`SpeechRecognition` / `webkitSpeechRecognition`). Браузер на Android
использует встроенный движок распознавания — бесплатно, без API-ключа,
без лимита минут, при любом числе пользователей. Сервер в голосовом
вводе больше не участвует.

## Объём изменений

### 1. `public/js/app.js` — механизм голосового ввода

Переписываются методы `initVoiceInput`, `startRecording`, `stopRecording`,
`transcribeBlob` (последний удаляется как ненужный). Методы `toggleVoice`,
`updateVoiceUI`, `setVoiceStatus` остаются почти без изменений.

- **`initVoiceInput()`** — проверяет наличие
  `window.SpeechRecognition || window.webkitSpeechRecognition`.
  Если API не поддерживается (старый браузер, часть iPhone) — кнопка
  «🎤 Голос» скрывается, остаётся ручной ввод.

- **`startRecording()`** — создаёт объект распознавания с параметрами:
  - `lang = 'ru-RU'`
  - `continuous = true` — распознавание не обрывается на паузах
  - `interimResults = true` — промежуточный (живой) текст
  Запоминает «базовый» текст, который был в textarea до начала записи.

- **`onresult`** — формирует содержимое textarea вживую:
  - завершённые (`isFinal`) фразы — каждая с новой строки;
  - текущая незавершённая фраза — дописывается в конце и обновляется
    по мере распознавания.
  Каждая пауза в речи = новая строка = отдельная запись для парсера.

- **`onerror`** — выставляет статус под кнопкой по типу ошибки.
- **`onend`** — сбрасывает состояние записи, обновляет UI.

- **`stopRecording()`** — вызывает `recognition.stop()`, финализирует
  текст, возвращает кнопку в состояние «🎤 Голос».

### 2. `public/service-worker.js`

Поднять версию кэша `brigade-v12` → `brigade-v13`, чтобы клиенты
подтянули обновлённый `app.js`.

### 3. Что НЕ трогаем

- **Сервер** — endpoint `/api/transcribe` и код Hugging Face остаются
  в коде (решение пользователя «оставить пока»). После переписывания
  клиента этот endpoint никто не вызывает — он становится «спящим».
  Чтобы вернуться к серверной схеме, достаточно восстановить клиентский
  вызов; серверную часть переписывать не придётся. `HF_TOKEN` сохраняется.
- **Парсер** (`server/parser.js`) — без изменений.
- **CSS** — класс `.voice-btn.recording` с пульсацией уже есть.

## Поток данных

```
Микрофон → встроенный движок распознавания браузера → текст в textarea
```

Сервер не участвует. Интернет нужен (как и раньше с Hugging Face).

## Маппинг фраз на строки

Парсер обрабатывает textarea построчно: одна строка = одна запись
(«квартал/клетка: сотрудник — ряды»). Поэтому каждая завершённая фраза
Web Speech API записывается отдельной строкой. Пример: бригадир говорит
«иванов с первого по пятый» *(пауза)* «петров шестой седьмой» →
в поле появляются две строки.

## Обработка ошибок

| Событие | Статус под кнопкой |
|---|---|
| `not-allowed` / `service-not-allowed` | ❌ Нет доступа к микрофону |
| `no-speech` | ⚠ Речь не распознана |
| `network` | ❌ Нет сети |
| API не поддерживается | кнопка скрыта, ручной ввод |

## Тестирование

- Web Speech API — браузерный API, в Node не запускается.
  Автоматический тест — только `node --check public/js/app.js`
  (проверка синтаксиса).
- Основная проверка ручная: открыть приложение на Android-телефоне,
  надиктовать фразу, убедиться, что текст появляется построчно и
  корректно обрабатывается кнопкой «Обработать».

## Вне объёма (YAGNI)

- Удаление серверного кода Hugging Face — отложено.
- Выбор языка распознавания — жёстко `ru-RU`.
- Офлайн-распознавание — голос требует интернет.
- Поле «виды работ» — отдельная будущая фича, не входит в эту задачу.
- Исправление бага парсера с хвостовым словом «ряд» — отдельная задача.
