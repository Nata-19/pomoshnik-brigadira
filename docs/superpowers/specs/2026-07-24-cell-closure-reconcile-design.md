# Закрытие клетки по виду работ на «Сверке» — дизайн

**Дата:** 2026-07-24  
**Статус:** утверждён к реализации (согласовано с Наталией)  
**Область:** вкладка «Сверка»; демо и прод — один код. Реализация — мелкими шагами (риск отключения света).

## 1. Зачем

Бригадиру нужно видеть, где по конкретному виду работ клетка уже «снята с людей» (можно опрыскивать / перевести бригаду), а где ещё идут работы или есть хвосты (пропуски, спорные).

Сейчас «Сверка» показывает сделано/осталось по **квартал + клетка + вид**, но нет метки «закрыто» и нельзя одним запросом посмотреть **весь квартал** по виду работ.

## 2. Что это такое / что нет

**«Закрыто»** — метка для бригадира (логистика поля).  
**Не** запрет ввода рядов на «Ввод данных».  
**Не** обязательная часть отчёта агроному (га) или бухгалтеру (кусты) в этой задаче.

Ключ метки: **хозяйство + квартал + клетка + вид работ**  
(+ владелец: в демо `demo_session_id`, в проде `brigadier_id`).  
Другие виды работ на той же клетке закрываются отдельно.

## 3. Поведение

### Закрыть / Открыть

- **Закрыть** — доступно только если по сверке **нет пропущенных рядов и нет спорных** (эквивалент `fullyDone` из текущего `/api/rows-status`). Иначе сервер отвечает ошибкой с понятным текстом.
- **Открыть** — снять метку в любой момент (ошиблись / люди снова вышли).
- После закрытия ввод по этой клетке+виду **технически можно**; смысл метки — «бригада здесь уже не работает».

### Режим «одна клетка» (как сейчас + кнопки)

Фильтры: квартал, клетка, вид работ → «Показать».  
Результат: текущая сводка сверки + статус **Открыта / Закрыта** + кнопка **Закрыть** или **Открыть**.

### Режим «весь квартал» (новое)

Фильтры: квартал, вид работ, **клетка пустая** → «Показать».  
Список всех клеток квартала (из инвентаря). У каждой клетки:

| Поле | Смысл |
|------|--------|
| Номер клетки | |
| Статус | `Закрыта` / `Готова` (можно закрыть) / `Есть пропуски` / `Есть спорные` (спорные приоритетнее пропусков в подписи, если оба) |
| Коротко цифры | сделано / осталось (ряды; кусты — как в текущей сверке, если уже считаются) |

Тап по клетке в списке → открывает детальный вид этой клетки (как режим «одна клетка»), клетка подставляется в селект.  
У строки со статусом **Готова** — кнопка **Закрыть**; у **Закрыта** — **Открыть** (без обязательного перехода в детальный вид).

Заголовок блока: **«Сверка»** (убрать узкое «по клетке»).

## 4. Данные

Таблица `cell_closures`:

```text
id SERIAL PK
estate_id TEXT NOT NULL
quarter TEXT NOT NULL
cell TEXT NOT NULL
work_type TEXT NOT NULL
brigadier_id INTEGER NULL          -- прод
demo_session_id TEXT NULL         -- демо, FK CASCADE на demo_sessions
closed_at TIMESTAMPTZ DEFAULT now()
closed_by TEXT NULL               -- опционально: имя/логин бригадира; можно отложить
UNIQUE по владельцу + estate + quarter + cell + work_type
```

- Строка есть → закрыто.  
- `DELETE` строки → открыто.  
- Сброс демо-сессии каскадом чистит метки.

Не хранить «закрыто» в `work_logs` и не в localStorage.

## 5. API

Владение и trim `work_type` — как у `/api/rows-status`.

| Метод | Назначение |
|-------|------------|
| `GET /api/rows-status` | Как сейчас **плюс** поле `closed: boolean`. Параметры без изменений (клетка обязательна). |
| `GET /api/rows-status/quarter` | Новое: `estate`, `quarter`, `work_type` (без cell). Ответ: `{ cells: [{ cell, …сводка сверки, closed, statusLabel }] }` по всем клеткам квартала из инвентаря. |
| `POST /api/cell-closures` | Тело: `{ estate, quarter, cell, work_type }`. Сервер пересчитывает сверку; если не `fullyDone` → **400** с текстом вроде «Нельзя закрыть: есть пропуски или спорные». Если уже закрыто → **200** идемпотентно. |
| `DELETE /api/cell-closures` | Тело или query: тот же ключ. Нет строки → **200** идемпотентно. |

Существующая логика `computeCellReconciliation` не ломается — переиспользуется.

## 6. UI (фронт)

- Селект клетки: первая опция «Все клетки…» / пустое значение = режим квартала.
- `loadRowsStatus`: если cell пустой → `GET .../quarter`; иначе текущий путь + кнопки закрытия.
- Кнопка «Закрыть» disabled или скрыта, если `!fullyDone` или уже `closed`.
- После успешного Закрыть/Открыть — перезагрузить текущий вид.

Гид (одна подсказка): обновить текст про Сверку — можно смотреть клетку или весь квартал; закрытие = метка для бригадира.

## 7. Что не меняем

- «Ввод данных», контроль рядов, спорные (кроме учёта при проверке закрытия).
- «Выполнение» / формат агроному — без обязательного показа «закрыто» в MVP.
- Бухгалтерия, Excel.
- Блокировка `POST /api/logs` по закрытой клетке.

## 8. Критерии готовности

- [ ] На клетке без пропусков/спорных можно Закрыть; метка видна после перезагрузки.
- [ ] С пропусками или спорными Закрыть нельзя (UI + сервер).
- [ ] Открыть снимает метку.
- [ ] Режим без клетки: список клеток квартала со статусами; тап → детальная сверка.
- [ ] Другой вид работ на той же клетке закрывается отдельно.
- [ ] Демо-сброс сессии убирает метки; прод/демо один код поведения.

## 9. Порядок реализации (ориентир для плана)

Мелкими коммитами из‑за света:

1. Таблица + POST/DELETE closures + `closed` в `GET /api/rows-status`.  
2. Кнопки **Закрыть/Открыть** в режиме одной клетки **и** в режиме квартала (в детальном виде клетки и/или у строки клетки в списке — где бригадир видит статус и может закрыть готовую).  
3. `GET .../quarter` + список клеток на Сверке (если ещё не закрыто шагом 2 вместе с UI списка).

Уточнение к шагу 2: закрытие доступно и когда смотришь одну клетку, и когда смотришь весь квартал (у клетки со статусом «Готова» — действие Закрыть; у «Закрыта» — Открыть).
