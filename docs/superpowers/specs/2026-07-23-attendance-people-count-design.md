# К-во человек в явке (права бригадира) — дизайн

**Дата:** 2026-07-23  
**Статус:** утверждён к реализации (согласовано с Наталией)  
**Область:** явка на «Ввод данных» + отображение в «Всего за день». Демо и прод — один код.

## 1. Зачем

Бригадир утром отмечает, кто на поле, и фиксирует численность (позже — сводка агроному; в этой задаче только сохранение числа). В этом хозяйстве почти все — приезжие бригады (фамилия + сколько человек приехало сегодня). Число каждый день своё: сегодня у Халила 10, завтра 8 или 12 — его нельзя «приклеить» к фамилии в справочнике.

Нужно: напротив отмеченной фамилии вписать **к-во чел. на сегодня**; вечером ряды — как сейчас; в отчёте за день видеть, например: **Халил 10 чел. — 60 рядов, 3000 кустов**.

## 2. Что меняем / что не трогаем

### Меняем

1. **Явка** — у плашки «сегодня на работе» опциональное поле числа.
2. **Хранение** — `attendance.people_count` (на дату + сотрудника).
3. **«Всего за день»** — рядом с именем показывать к-во чел., если задано.

### Не меняем в этой задаче

- Справочник сотрудников (без меток «устроенный / приезжий»).
- Вечерний ввод рядов, подсветка, контроль рядов, спорные.
- Блок «Записи за дату» (список с ✕) — без обязательной правки; достаточно «Всего за день».
- Вкладка «Бухгалтерия», Excel, расценки, транспорт, бригадирские.
- Отдельный режим «факт без рядов».
- Рассылка агроному (MAX/почта) — позже; данные уже будут в явке.

## 3. Поведение UI

### Утро — явка (блок «Сегодня на работе»)

1. Как сейчас: «Выбрать рабочих из бригады» → галочка → фамилия появляется в плашках под списком.
2. На плашке: **имя** + компактное поле числа (пусто по умолчанию).
3. Тап по **имени** — выбор сотрудника для ввода рядов (синяя `.on`), без изменений.
4. Ввод числа в поле — сохранение `people_count` для этой даты (целое ≥ 1). Очистка поля — сброс в `null` (без численности).
5. Число **не** пишется в `employees` и **не** переносится на следующий день.

Устроенный (или без численности): поле оставляют пустым.

### Вечер

Без изменений: тап по плашке → ряды / диапазон → «Добавить».

### «Всего за день»

Строка работника, если есть `people_count`:

```text
Халил 10 чел. — 60 рядов, 3000 кустов · Кв.…, клет.…
```

Если `people_count` пусто — как сейчас (`Халил — 60 рядов, 3000 кустов · …`).

Источник числа: явка на ту же дату, сопоставление по `employee_id` / имени из `present`. В `work_logs` к-во чел. **не** дублируем.

## 4. Данные и API

### Схема

```sql
ALTER TABLE attendance ADD COLUMN IF NOT EXISTS people_count INTEGER;
-- NULL = не указано; иначе целое >= 1
```

Первичный ключ явки без изменений: `(brigadier_id|demo_session_id, date, employee_id)`.

### API

| Метод | Изменение |
|-------|-----------|
| `GET /api/attendance?date=` | В каждом элементе `present[]` добавить `people_count` (`number \| null`). |
| `POST /api/attendance` | Как сейчас: только отметить присутствие (без числа). |
| `PATCH /api/attendance` | Обновить `people_count` у уже отмеченного: `{ date, employee_id, people_count }`. |

Валидация PATCH: дата `YYYY-MM-DD`; `employee_id` из бригады/сессии; запись явки должна существовать; `people_count` — `null` (сброс) или целое 1…999.

`DELETE /api/attendance` — как сейчас (строка явки удаляется вместе с числом).

## 5. Ошибки и крайние случаи

- Не отмечен, а число вводят — нельзя: поле только на плашках уже присутствующих.
- Сняли с явки — запись attendance удалена, число пропало (ок).
- Смена даты на «Ввод данных» — подгружается явка за новую дату (числа другого дня не видны).
- Офлайн: то же поведение, что у текущей явки (если явка уже уходит в очередь — `people_count` в том же запросе/патче).

## 6. Критерии готовности

- [ ] На плашке можно вписать и очистить к-во чел.; после перезагрузки страницы число на месте.
- [ ] Завтра у той же фамилии поле снова пустое, пока не введут.
- [ ] Вечерний ввод рядов не изменился.
- [ ] «Всего за день» показывает `Имя N чел. — …`, только если число задано.
- [ ] Демо и прод работают одинаково.

## 7. Вне скоупа (следующие задачи)

- Отдельная сводка агроному «сколько человек на поле» (копирование / MAX).
- Показ к-во чел. в «Отчёт за период» / Журнале — по желанию позже; в MVP достаточно дня.
