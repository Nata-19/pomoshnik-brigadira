# Разбивка к-во чел. по виду работ и кварталу — дизайн

**Дата:** 2026-07-24  
**Статус:** черновик на ревью Наталии  
**Область:** «Ввод данных» (явка + разбивка численности). Демо и прод — один код.  
**Контекст:** шаг 1 перед вкладкой «Бухгалтерия»; без этой разбивки строки Excel с разным к-во чел. по видам работ собрать нельзя.

## 1. Зачем

Утром бригадир отмечает явку и общее число людей у фамилии (например Халил — **10**): это для агронома и база для транспорта/бригадирских.

Иногда бригаду **делят** по видам работ и кварталам (редко): 6 на обрезке в кв.9, 4 на подготовке саженцев в кв.1. Числа нужны бухгалтерии в разных строках.

Ещё реже: из приехавших кого-то **снимают с поля** (напились / брак в работе) — общее N уменьшают (10→8), от этого зависят оплаты × чел.

Обычный день (всех не делят): только явка + N, **без** обязательной разбивки — вечерние ряды/часы как сейчас.

## 2. Что меняем / что не трогаем

### Меняем

1. Хранение кусков разбивки: вид работ + квартал + число чел. на фамилию и дату.
2. UI: при выбранных виде работ и квартале можно задать число чел. на эту пару для отмеченного в явке.
3. Правила согласования кусков с общим N; уменьшение N на плашке (снятие с поля).

### Не меняем в этой задаче

- Вкладка «Бухгалтерия», Excel, норма/расценка/оплата/транспорт/бригадирские.
- Справочник сотрудников, вечерний ввод рядов/часов, контроль рядов, спорные, сверка.
- Рассылка агроному (MAX/почта).
- Обязательная правка «Всего за день» под куски разбивки (общее N на плашке и в дне — как сейчас).

## 3. Поведение UI

### Утро — явка (без изменений по смыслу)

1. Галочка в списке → плашка.
2. На плашке: имя + поле общего **N** (целое ≥ 1 или пусто).
3. Пустое N = без численности (устроенный / не указали) → разбивка для этой фамилии **не используется**.

### Разбивка по виду + кварталу

1. На экране выбраны **вид работ** и **квартал** (те же чипы/селекты, что для ввода рядов).
2. Сотрудник должен быть в явке и иметь общее N.
3. Задать кусок: выбрать сотрудника (тап по имени на плашке — как сейчас, синяя подсветка для ввода) и ввести число в поле **«чел. на этот вид / квартал»** (рядом с блоком ввода или под плашкой выбранного). Смена вида или квартала → другое число для новой пары.
4. Повторный ввод на ту же пару вид+квартал — правка куска (upsert).
5. Удаление куска — явное действие (очистка поля / ✕ у строки куска).

**Жесты не ломаем:** тап по имени по-прежнему выбирает человека для рядов/часов. Разбивка — отдельное поле числа при выбранных виде+квартале, не подмена выбора.

### Подписи на экране

- Если есть куски: кратко список или строка вида `обрезка · кв.9 — 6`.
- Если `0 < сумма кусков < N` — предупреждение: «Разбивка X из N» (день ещё идёт).
- Если сумма кусков `> N` — нельзя сохранить (см. API).
- Если вид или квартал не выбраны — поле разбивки недоступно, короткая подсказка.

### Снятие людей с поля

- Бригадир **уменьшает N** на плашке (10→8). Отдельной кнопки «выбыл» и истории выбытия в MVP нет.
- Если уже есть куски и новое N **меньше** суммы кусков — сначала поправить/удалить куски, иначе сервер отклонит смену N.

### Обычный день без деления

- Разбивки нет → ок. Общее N и вечерний ввод как сейчас.
- Бухгалтерия (следующая задача) в этом случае подставит N в строку сама.

## 4. Данные

Таблица `people_allocations`:

```text
id SERIAL PK
date TEXT NOT NULL                 -- YYYY-MM-DD
employee_id INTEGER NOT NULL
work_type TEXT NOT NULL            -- trim, как в work_logs
quarter TEXT NOT NULL
people_count INTEGER NOT NULL      -- целое 1…999
brigadier_id INTEGER NULL          -- прод
demo_session_id TEXT NULL         -- демо, FK CASCADE на demo_sessions
UNIQUE по владельцу + date + employee_id + work_type + quarter
```

- Не хранить куски в `work_logs` и не в JSON явки.
- Сняли с явки (`DELETE attendance`) → удалить все куски этого сотрудника за дату (тот же владелец).
- Сброс демо-сессии — каскад чистит куски.

`attendance.people_count` — по-прежнему общее N на день (агроном + потолок разбивки).

## 5. API

Владение — как у явки (demo_session_id / brigadier_id).

| Метод | Назначение |
|-------|------------|
| `GET /api/people-allocations?date=` | Список кусков за день (для текущего владельца). |
| `PUT /api/people-allocations` | Upsert: `{ date, employee_id, work_type, quarter, people_count }`. |
| `DELETE /api/people-allocations` | Удалить кусок: `{ date, employee_id, work_type, quarter }`. |

Валидация PUT:

- Дата `YYYY-MM-DD`; сотрудник в явке на эту дату; у явки задано N (`people_count` не null).
- `work_type` непустой после trim; `quarter` непустой; `people_count` целое 1…999.
- После upsert сумма кусков по (сотрудник+дата) **≤ N**; иначе `400` с текстом вроде «Сумма разбивки больше явки (N)».
- Сумма **< N** при наличии кусков — **разрешена** (предупреждение только на клиенте): чтобы можно было сначала сохранить 6, потом 4.

Валидация DELETE куска: кусок существует; владение ок.

Дополнение к `PATCH /api/attendance` (people_count):

- Новое N = `null` (сброс): если есть куски за сотрудника+дату — либо `400` («сначала удалите разбивку»), либо каскадно удалить куски. **Выбор для реализации: каскадно удалить куски** (проще на поле).
- Новое N = число: если сумма кусков **> N** — `400` («разбивка X больше нового N; поправьте куски»).
- Новое N ≥ суммы кусков (или кусков нет) — ок.

`DELETE /api/attendance` — как сейчас + удаление кусков за эту дату/сотрудника.

## 6. Ошибки и крайние случаи

| Ситуация | Поведение |
|----------|-----------|
| Нет N в явке, пытаются писать кусок | Отказ: сначала общее число на плашке. |
| Нет вида работ или квартала | Поле разбивки неактивно. |
| Все на одном виде, разбивку не трогали | Ок, кусков нет. |
| Делят 6+4 | Два куска; сумма 10 = N; предупреждение снимается. |
| Сняли двоих с поля | N: 10→8; куски поправить, если сумма была 10. |
| Сняли фамилию с явки | Куски за день удалены. |
| Офлайн | Как у явки: те же запросы в очереди, если очередь уже есть для attendance; иначе — поведение текущего офлайна проекта (не расширяем офлайн отдельно в этой задаче). |

## 7. Критерии готовности

- [ ] Утро: явка + N сохраняются как сейчас.
- [ ] Можно сохранить кусок на вид+квартал; после перезагрузки куски на месте.
- [ ] Два куска на разные вид+квартал; сумма ≤ N; сумма > N не сохраняется.
- [ ] Пока сумма < N — на экране «Разбивка X из N», данные при этом сохранены.
- [ ] Без кусков день работает как раньше (ряды/часы).
- [ ] Уменьшение N на плашке при сумме кусков > нового N — отказ с понятным текстом.
- [ ] Сброс N / снятие с явки — куски не остаются «висеть».
- [ ] Демо и прод одинаково.

## 8. Вне скоупа (следующие задачи)

- Вкладка «Бухгалтерия» + Excel за один день, 1 лист = 1 бригада (фамилия), строки = вид работ + квартал; «Факт» = кусты или часы; пустые колонки под бухгалтера.
- В строке Excel: к-во чел. из куска разбивки, если сумма кусков = N; если кусков нет — общее N явки на единственную/каждую строку по правилам бухгалтерии (уточнить в спеке бухгалтерии).
- Год посадки / сорт из inventory (боевой файл позже; в демке — фейк).
- Почта / MAX.
