# Demo Helper — Design Spec

**Дата:** 2026-05-23
**Статус:** Утверждён к реализации
**Автор обсуждения:** Натали + ассистент

## Цель

Витрина-демо «Помощьник Бригадира» для публикации в ВК и в группе агрономов. Цель — показать функционал потенциальным клиентам (бригадирам виноградников и садов). После знакомства — конвертация в звонок Натали (+79783116389) для индивидуальной настройки под предприятие.

Демо НЕ конвертируется в боевой аккаунт автоматически — все продажи через звонок и индивидуальную настройку.

## Архитектура

### Один код, два деплоя

Переменная окружения `DEMO_MODE`:
- `true` → демо-режим;
- `false` или отсутствует → боевой.

Один и тот же репозиторий, один код, два независимых деплоя:
- **Боевой** — Render + Neon (как сейчас), `DEMO_MODE` не установлен.
- **Демо** — отдельный хостинг + отдельный Neon-проект, `DEMO_MODE=true`.

**Безопасность переключателя.** При старте сервер делает ассерт: если `DEMO_MODE=true` И `DATABASE_URL` содержит подстроку, указывающую на боевую базу (точный паттерн определяется при реализации, например начало connection string боевой Neon-инстанции) — отказ запуска с ошибкой. Защита от случайного включения демо-режима в продакшене.

### Изоляция данных в демо

Каждый посетитель получает уникальный `demo_session_id` в cookie при первом заходе. TTL cookie — 24 часа.

**Схема БД:**
Все таблицы данных получают колонку `demo_session_id TEXT` (миграция при `DEMO_MODE=true`).

Затронуты как минимум:
- `employees` (сотрудники)
- `work_types` (виды работ)
- `attendance` (явка)
- `work_logs` (записи работ)
- новая таблица `demo_quarters` и `demo_cells` (упрощённый инвентарь для демо, без боевых хозяйств)

**Middleware:**
На каждом запросе к API в демо-режиме middleware:
1. Читает `demo_session_id` из cookie. Если нет — создаёт новую сессию и копирует «заводское наполнение».
2. Прикрепляет `req.demo_session_id`.
3. Все SQL-запросы фильтруются по этому значению (`WHERE demo_session_id = $1`).

**Очистка устаревших сессий — ленивая.**
При каждом входящем запросе с вероятностью ~1% (или раз в N минут через простой in-process таймер) выполняется:
```sql
DELETE FROM employees WHERE demo_session_id IN (
  SELECT id FROM demo_sessions WHERE created_at < NOW() - INTERVAL '24 hours'
);
-- то же для остальных таблиц
DELETE FROM demo_sessions WHERE created_at < NOW() - INTERVAL '24 hours';
```

Отказ от cron-задач: на Render Free сервис спит, cron может не сработать. Ленивая очистка надёжнее.

## UI отличия в `DEMO_MODE`

### Шапка
- Название: **«Демо Помощник»**
- Лого: **🌱**
- Плашка-баннер вверху: **«🎯 Это демо. Данные удалятся через сутки. Понравилось — звоните Натали +79783116389»**. На мобильном — сворачивается в выпадающее «ℹ Что это?».
- Скрыты: кнопка «Выйти», плашка имени бригадира.
- Опциональная кнопка **«🔄 Начать сначала»** — с подтверждением «Точно? Все твои записи удалятся». При подтверждении — сброс этой сессии, новая выдача заводского наполнения.
- Опциональная кнопка **«🎓 Запустить гайд снова»** — после прохождения гайда.

### Хозяйство / культура

При первом заходе плашка хозяйства пустая. Гайд первым шагом указывает «введи свою культуру».

Посетитель вводит свободный текст (например, «виноград», «яблоня», «черешня», «клубника»). Создаётся хозяйство «Демо: <культура>» с заводским наполнением.

**Определение единицы учёта (куст / дерево / растения):**
- Словарь «кустовых» (виноград, малина, смородина, ежевика, крыжовник, клубника, голубика, жимолость) → куст.
- Словарь «древесных» (яблоня, груша, слива, персик, абрикос, вишня, черешня, алыча, орех) → дерево.
- Неизвестное слово → три кнопки «Кусты / Деревья / **Другое**». «Другое» использует общий термин «растений».

Единица учёта хранится **на уровне квартала**, не хозяйства. В одном демо-хозяйстве могут быть кварталы с разными единицами (если пользователь добавит дополнительные кварталы — он сам выберет единицу для каждого).

### Контекст ввода работы — две плашки

Рядом с обычной плашкой «Вид работ» (ручные) добавляется вторая — **«Механизированные работы»**.

Бригадир выбирает ОДНУ из двух на каждую запись (не обе).

Каждая плашка имеет кнопку **«➕ Добавить свой»** для пополнения списка.

### Режим «Как считать» — 5 единиц в демо

1. Ряды + Кусты/Деревья/Растения (зависит от единицы квартала)
2. Только ряды
3. Часы
4. Гектары
5. Километры (для перегона трактора)

Под плашкой — мягкая ссылка:
> **❓ Нужны другие единицы (тонны, столбы, погонные метры, комбинированные)? Настраивается под предприятие — звоните Натали +79783116389**

**Архитектура в коде поддерживает все 11 единиц.** В демо включены 5 через конфигурацию. Для будущих индивидуальных установок — меняется конфиг, единицы появляются.

### Дефолтный режим у каждого вида работ

При создании / настройке вида работ задаётся «единица подсчёта по умолчанию». Когда бригадир выбирает вид работ в плашке — нужные поля появляются автоматически. Бригадир может вручную переключить режим, если требуется нестандартное.

Заводские дефолты:
- Обрезка → Ряды + Кусты/Деревья
- Полив → Ряды + Кусты/Деревья
- Прополка → Ряды + Кусты/Деревья
- Опрыскивание → Гектары
- Культивация → Гектары
- Перегон трактора → Километры

### UX механизированных работ — детали TBD

Ждём ответа от мужа Натали (бригадир). Сейчас известно:
- Тракторист обычно обрабатывает несколько смежных клеток («с 1 по 5»).
- В одну поездку делает диапазон рядов (например, «с 60 по 120»).
- Иногда едет каждый ряд, иногда через ряд.
- Куда привязывать «перегон трактора» (один квартал? пара «откуда-куда»?) — тоже TBD.

Предварительные поля для механизированной работы:
- Квартал
- Диапазон клеток (с N по M)
- Диапазон рядов (с N по M)
- Шаг (каждый ряд / через ряд)
- Сотрудник (тракторист — из общего списка сотрудников)
- Гектары (вычисляются автоматически на основе диапазонов? или вводятся вручную? — уточнить)

Эти поля и UX финализируются после ответа мужа.

### Отчёт за период — два блока

- 🛠 **Ручные работы** — группировка как в боевом: сотрудник → вид работ → клетка → итоги.
- 🚜 **Механизированные работы** — отдельный блок ниже, аналогичная группировка но в единицах механизированных работ (гектары/километры/часы).
- Внизу — итог за день и итог за период с разделением «руками N, техникой M».

### Журнал в новом формате

**Важно: сначала переделываем в боевом отдельным коммитом, потом копируем в демо.** Это снижает риск что баг в демо-версии поедет в боевое позже.

Формат отображения записей:
```
[Дата: вчера]   Обрезка   Кв.1, клет.1
   Иванов — 5 рядов, 685 кустов
   Петров — 4 ряда, 555 кустов

[Дата: вчера]   Подвязка   Кв.1, клет.2
   Сидоров — 3 ряда, 410 кустов

[Дата: позавчера]   Опрыскивание   Кв.2
   Сидоров — 8 гектаров
```

Группировка: **дата → вид работ → клетка → столбиком работники с цифрами**.

## Заводское наполнение

Логика двухэтапная.

### Этап А: При создании сессии (первый заход в демо)

Копируется в новую сессию **до ввода культуры**, доступно сразу:

- **3 сотрудника:** Иванов, Петров, Сидоров.
- **3 ручных вида работ:** Обрезка, Полив, Прополка (все с режимом «Ряды + Кусты/Деревья» по умолчанию).
- **3 механизированных вида работ:** Опрыскивание (Гектары), Культивация (Гектары), Перегон трактора (Километры).

Эти справочники не зависят от культуры и одинаковы для всех демо-сессий.

### Этап Б: При вводе культуры (создание хозяйства)

Когда посетитель впервые вводит культуру в плашку хозяйства, создаётся:

- **1 хозяйство** с названием «Демо: <культура>». Единица учёта — куст / дерево / растения по словарю или выбору посетителя.
- **2 квартала**, в каждом 5 клеток. Все кварталы получают ту же единицу учёта что хозяйство.
- **Инвентарь** рядов и кустов/деревьев в клетках (реалистичные цифры из стандартного набора, например 137-150 кустов в ряду).
- **Площадь клеток** в гектарах (для режима «Гектары» механизированных работ).
- **2-3 записи в журнале за вчера и позавчера** для примера. Используют сотрудников и виды работ из Этапа А. Формат см. выше («Журнал в новом формате»).
- **Явка сотрудников** на вчера и позавчера — отмечены те трое.

Если посетитель введёт ВТОРУЮ культуру в плашке хозяйства (например, после винограда введёт «яблоня») — создаётся второе хозяйство «Демо: яблоня» с тем же набором кварталов и записей, но единицей учёта «дерево». Сотрудники и виды работ — общие для всех хозяйств сессии (из Этапа А).

## Пошаговый гайд

### Технология
Своя реализация без сторонних библиотек (~150 строк JS). Overlay-маска с прорезью на нужном элементе UI, в углу мягкое «облачко» с текстом подсказки и кнопками **«Дальше»** / **«Понятно»** / **«Пропустить гайд»**.

Каждый шаг привязан к конкретному элементу UI через CSS-селектор. Каждый шаг ждёт пока посетитель выполнит ожидаемое действие (клик / выбор / ввод), и только тогда переходит дальше.

### Структура — 4 главы

Между главами — кнопка **«Продолжить или закрыть»**. Посетитель может уйти после Главы 2 и это нормально.

**Глава 1: Знакомство (3 шага)**
1. Приветственное окно: «Привет! Это демо. Покажу за пару минут как им пользоваться. Всё что ты введёшь — твоё, никто не увидит. Через сутки всё стирается.»
2. Подсветка плашки хозяйства: «Введи свою культуру».
3. (Если культура неизвестна) «У тебя кусты, деревья или другое?» — три кнопки.

**Глава 2: Записываем ручную работу (8 шагов)**
4. «Здесь у тебя 2 квартала по 5 клеток. Они уже заполнены реальной структурой рядов и кустов. Открой вкладку Ввод данных.»
5. «Отметь явку сотрудника — нажми на Иванова.»
6. «Выбери квартал — Кв.1.»
7. «Выбери клетку — клет.1.»
8. «В плашке "Вид работ" (ручные) — выбери Обрезка.»
9. «Видишь — автоматически появилось "Ряды + Кусты". Это режим по умолчанию для Обрезки. Можно переключить вручную.»
10. «Введи ряды — 1-3.»
11. «Жми Добавить. Готово!»

**Глава 3: Журнал и механизированная работа (7 шагов)**
12. «Открой вкладку Журнал. Видишь — твоя запись там, рядом с примерами за вчера-позавчера.»
13. «Теперь попробуем механизированную работу. Открой Ввод данных.»
14. «Отметь явку другого сотрудника — Петрова.»
15. «Выбери Кв.2.»
16. «На этот раз выбери из плашки "Механизированные работы" — Опрыскивание.»
17. «Появилось поле "Гектары". Введи 5.»
18. «Жми Добавить.»

**Глава 4: Отчёт и завершение (3 шага)**
19. «Открой Отчёт за период.»
20. «Выбери диапазон — последние 3 дня. Видишь — отчёт разделён на 🛠 Ручные и 🚜 Механизированные. Внизу итоги.»
21. Финальное окно: «Готово! Ты прошёл всё основное. Сейчас экспериментируй — добавь своих сотрудников, свои виды работ, попробуй разные режимы. Через сутки всё сбросится. Понравилось — звоните Натали: +79783116389»

### Прогресс гайда
- Хранится в localStorage (для устойчивости к перезагрузкам).
- Если посетитель прервался — при следующем заходе «Продолжить с того места?»
- Пройдённый гайд — кнопка «🎓 Запустить гайд снова» в шапке.
- **Простой счётчик «дошёл до шага N»** в localStorage для будущего анализа. Раз в неделю можно вручную смотреть статистику.

### Пропустить гайд
В углу облачка подсказки кнопка **«✕ Пропустить гайд»**. Один клик — гайд скрывается до сброса сессии.

## Что НЕ делаем в первой версии

- Регистрация / аккаунты в демо.
- Сохранение прогресса дольше суток (никаких PDF, email).
- Превращение демо в боевой аккаунт.
- Аналитика поведения посетителей (только простой счётчик гайда).
- Новые цвета / фавиконка (только лого меняется на 🌱).
- Импорт Excel посетителем.
- Встроенный чат / форма обратной связи.
- Создание дополнительных хозяйств одной кнопкой (только через ввод новой культуры в плашку).
- PWA-установку демо специально не тестируем.
- Поддержка 6 «расширенных» единиц измерения (тонны, столбы, погонные метры, комбинированные) — продаётся как «настраивается под предприятие».

## Безопасность

- Ассерт при старте: `DEMO_MODE=true` + боевой `DATABASE_URL` → отказ запуска.
- В демо-режиме отключены маршруты: `/api/register`, `/api/login`, `/api/logout`, `/api/setup`, `/api/admin/*`, `/api/me`.
- В демо-режиме включён новый маршрут `/api/demo/session` — создаёт новую сессию, выдаёт cookie, копирует заводское наполнение.
- В демо-режиме включён маршрут `/api/demo/reset` — для кнопки «Начать сначала» (с подтверждением на фронте).
- Все остальные маршруты в демо-режиме обёрнуты middleware-фильтром по `demo_session_id`.

### Промежуточные сверки
После каждого этапа я пишу короткий отчёт Натали: «Готов этап N, что протестировать локально, какие тебе вопросы по дизайну». Натали идёт по чек-листу и говорит «да/нет/поправь». Это удобнее чем «исчезнуть на 3 недели и выкатить целиком».

### Что параллельно от Натали

2. Определиться с хостингом для демо — нужно к Этапу 9 (~начало третьей недели).
