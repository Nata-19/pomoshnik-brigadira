# Контроль рядов Фаза 3 — «Ряды клетки»: пропущенные ряды + сверка по клетке

**Дата:** 2026-06-07
**Статус:** утверждён к реализации
**Область:** боевой + демо (общий код контроля рядов). Продолжение Фаз 1–2 и дробного учёта.

## 1. Зачем

Бригадиру нужно видеть, что по клетке ещё **не пройдено** (забытые ряды), и **сверить клетку**: сделана целиком или сколько осталось. Все ряды, не записанные на рабочего (пропущенные + спорные), считаются «осталось».

Экран — **только просмотр** (Вариант А). Действий на нём нет: проверив пропущенный ряд, бригадир идёт на «Ввод данных» и записывает (сделан → на того, кто сделал; не сделан → ставит рабочих).

## 2. Что показываем

Новая вкладка **«Сверка»**. Бригадир выбирает **квартал + клетку + вид работ**. Экран показывает:

**Сверка по клетке** (числа по инвентарю, всегда сходятся «сделано + осталось = всего»):
- Клетка сделана полностью → «Клетка сделана полностью: N рядов, M кустов».
- Иначе → «Сделано: X рядов, Y кустов · Осталось: Z рядов, W кустов».
- Если есть спорные ряды → пометка «в т.ч. K спорных — см. вкладку Спорные».

**Список несделанных рядов** — номера рядов, не записанных на рабочего:
- **пропущенные** — без пометки (забытые, не в журнале и не в спорных);
- **спорные** — с пометкой «спорный» (⚠️), их разбирают на вкладке «Спорные».
Компактно, одним списком.

## 3. Правила расчёта (по инвентарю, с учётом долей)

Разрез: хозяйство (estate) + квартал + клетка + вид работ. Накопительно (за всё время, дата не фильтруется).

- **Всего по клетке:** `totalRows` = число рядов клетки в инвентаре; `totalBushes` = сумма кустов этих рядов по инвентарю.
- **Вес ряда** = сумма `row_weights` по этому ряду из всех записей `work_logs` в разрезе (поделённый ряд = доля; целый = 1; ряд без записи = 0). Старые записи без `row_weights` → ряд считается весом 1 (как в дробном учёте).
- **Сделано:** `doneRows` = Σ вес_ряда (дробно); `doneBushes` = Σ (вес_ряда × кусты_ряда по инвентарю), округление кустов до целого.
- **Осталось:** `remainingRows = totalRows − doneRows`; `remainingBushes = totalBushes − doneBushes` (зажать в ≥0).
- **Пропущенные ряды (`missedRows`):** ряды инвентаря с весом 0 И не входящие в `disputed_rows`.
- **Спорные (`disputedRows`, `disputedCount`):** номера и число рядов клетки в `disputed_rows` (в этом разрезе). Они входят в «осталось» (вес 0). В `missedRows` не попадают, но в общем списке несделанных показываются с пометкой «спорный».
- **`fullyDone`:** `remainingRows` округлённо равно 0 (всё пройдено, нет пропущенных и спорных).

## 4. Архитектура

**Чистое ядро** — функция в `server/rowControl.js` (под юнит-тесты, без БД/HTTP):

`computeCellReconciliation(inventoryRows, weightByRow, disputedSet)`:
- `inventoryRows`: `[{ row:Number, bushes:Number }]` — ряды клетки из инвентаря.
- `weightByRow`: `Map<Number, Number>` или объект `{row: weightSum}` — суммарный вес по ряду из журнала.
- `disputedSet`: `Set<Number>` — номера спорных рядов клетки.
- Возвращает `{ totalRows, totalBushes, doneRows, doneBushes, remainingRows, remainingBushes, missedRows:[Number], disputedRows:[Number], disputedCount, fullyDone }`.
- Дробные `doneRows`/`remainingRows` — точные; форматирование (2 знака) на клиенте через существующий `fmtRows`. Кусты — целые.

**Сервер** — `GET /api/rows-status?estate&quarter&cell&work_type` (demo-aware, `authOrDemo`):
1. Валидация параметров; `measure_mode` тут не нужен — берём все записи рядового вида (`rows_bushes`/`rows_only`) по виду работ. Проверка: вид работ задан, квартал+клетка заданы.
2. Инвентарь: `parserToUse` (demo: `new DataParser(await demo.getDemoInventory(...))`; прод: глобальный `parser`). Ряды клетки и кусты — из инвентаря (как `getHectaresForRows`/`getBushesCount` берут `_rowsOf(cellData)` и `row.bushes`).
3. `work_logs`: выбрать записи владельца по estate+quarter+cell+work_type с непустыми `rows`, режимы `rows_bushes`/`rows_only`; собрать `weightByRow` (через `rowControl.parseRowWeights`, ряд без веса = 1).
4. `disputed_rows`: номера рядов того же разреза.
5. Вызвать `computeCellReconciliation`, вернуть JSON.
   Пустой/неизвестный разрез (нет такой клетки в инвентаре) → 400 с понятным сообщением.

**Клиент** — новая вкладка «Сверка» в `public/js/app.js` + кнопка вкладки:
- Селекторы: квартал, клетка, вид работ (переиспользовать существующие списки/хелперы ввода).
- Кнопка «Показать» → `GET /api/rows-status` → рендер сверки + единого списка несделанных рядов (пропущенные без пометки, спорные с пометкой «спорный»).
- `fmtRows` для дробных рядов; кусты целые.
- Пустой результат/не выбрано — дружелюбные подсказки.

## 5. Крайние случаи

- **Клетка без рядов или без кустов в инвентаре:** 400/сообщение «нет данных по клетке» (как в существующих проверках инвентаря).
- **Частично сделанный ряд** (вес <1 — бывает только при ручном вводе долей): в `missedRows` НЕ попадает (он записан на рабочего), но его недостающая доля учтена в `remainingBushes`/`remainingRows`. Поведение задокументировано, не баг.
- **Ряд в журнале, которого нет в инвентаре клетки:** игнорируется в сверке (считаем по инвентарю клетки); веса учитываются только для существующих рядов.
- **Демо-режимы не-рядовые** (гектары/км/часы/столбы/тонны): экран для них не предназначен — вид работ рядовой; гард по `rows_bushes`/`rows_only` в выборке.
- **«Пересчёт уникальных рядов в отчёте»** из исходной спеки Фазы 3 — уже закрыт дробным учётом (отчёт суммирует веса), отдельно НЕ делаем.

## 6. Тестирование

- **Юнит (`node --test`, `test/rowControl.test.js`)** на `computeCellReconciliation`:
  - клетка сделана полностью → `fullyDone=true`, `missedRows=[]`, doneRows=totalRows.
  - частично → корректные done/remaining, `missedRows` = забытые.
  - со спорными → спорные не в `missedRows`, но есть в `disputedRows` и в остатке; `disputedCount` верный; сделано+осталось=всего.
  - дробный ряд (вес 0.5) → doneRows дробное, ряд не в missed, remainingBushes учитывает половину.
  - пустой инвентарь рядов → безопасно (нули/пусто).
- **Ручная проверка Натали** (демо, затем боевой): выбрать клетку, проверить сверку и список пропущенных; записать пропущенный на «Вводе» → исчезает из списка, сверка обновляется.

## 7. Что НЕ делаем (YAGNI)

- Действия на экране (записать/разобрать прямо отсюда) — только просмотр; ввод на своей вкладке.
- Показ полного списка ВСЕХ рядов со статусами — показываем только несделанные (пропущенные + спорные) и сводку.
- Разбор спорных прямо здесь — спорные только помечаются в списке, разбираются на вкладке «Спорные».
- Изменение модели данных — всё считается из существующих `work_logs.row_weights`, инвентаря и `disputed_rows`.
