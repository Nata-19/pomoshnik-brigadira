# Паспорт проекта «Помощьник Бригадира»

> Документ описывает систему в целом: архитектуру, состав, режимы работы и контуры.
> Читать перед тем, как разворачивать у покупателя или вносить крупные изменения.

---

## 1. Назначение

Мобильное веб-приложение для бригадиров виноградарского предприятия. Заменяет бумажные журналы: бригадир вводит выполненную работу прямо в поле с телефона, без интернета. Данные синхронизируются когда появляется сеть.

**Кто использует:** бригадиры (ввод работ), руководитель / учётчик (контроль рядов, сверка, отчёты).

---

## 2. Архитектура

```
[Телефон бригадира]  ←→  [Node/Express сервер]  ←→  [PostgreSQL]
   PWA (offline)              REST API                  постоянное
   app.js / SW                server.js                 хранилище
                              + модули (см. §3)
```

- **Сервер:** Node.js + Express, CommonJS, `pg` Pool.
- **Клиент:** Vanilla JS PWA — офлайн через Service Worker (`service-worker.js`), установка на экран телефона.
- **БД:** PostgreSQL. Таблицы создаются автоматически при старте (`server.js` → `ensureTables`).
- **Тесты:** встроенный `node --test` (CommonJS).

## 5. Данные

### 5.1 Инвентарь предприятия — `inventory.json`

Файл в корне проекта, **gitignored** (содержит данные конкретного предприятия).  
Структура: предприятия → кварталы → клетки → ряды + кусты + гектары.  
Генерируется парсером из Excel-таблицы клиента (через `parse_config.json`).

### 5.2 Таблицы PostgreSQL (создаются автоматически)

**Основные (реальный режим):**
- `brigadiers` — аккаунты бригадиров (логин, хэш пароля, привязка к кварталам)
- `employees` — список рабочих
- `work_types` — виды работ
- `work_logs` — журнал выполненных работ (ряды, кусты, гектары, часы, км)
- `attendance` — явка рабочих
- `disputed_rows` — спорные ряды (конфликты при вводе)

**Дополнительные (только DEMO_MODE):**
- `demo_sessions`, `demo_brigadiers`, `demo_employees`, `demo_work_types`
- `demo_work_logs`, `demo_attendance`, `demo_disputed_rows`
- `demo_quarters`, `demo_cells`, `demo_rows` — демо-инвентарь в БД

## 6. Режимы измерения

Настраиваются в `config.js`. Список всех поддерживаемых режимов (`MEASURE_MODES_ALL`):

| Режим | Что вводится |
|---|---|
| `rows_bushes` | ряды и кусты (основной виноградный) |
| `rows_only` | только ряды |
| `hours` | часы |
| `hectares` | гектары (механизированные работы) |
| `kilometers` | километры |
| `poles` | столбы |
| `tons` | тонны |
| `linear_meters` | погонные метры |
| `tons_km` | тонно-километры |
| `hours_km` | мото-часы/км |
| `hectares_tons` | гектары + тонны |

Набор под каждого клиента выбирается вручную и фиксируется в `config.js`.

---

## 7. Ключевые функции

- **Ввод работ** — выбор вида работы, рабочих, ввод рядов/кустов/гектаров/часов
- **Контроль рядов** — пересечения (один ряд двум бригадам), дробный учёт (деление ряда на N рабочих с долями 0.5 / 1.5), спорные ряды с модальным разрешением
- **Сверка** — сравнение учётных данных с фактом по кварталам
- **«Выполнение» (га)** — сколько сделано / осталось по видам работ и кварталам
- **Аккаунты бригадиров** — JWT-аутентификация, пароль ≥ 8 символов, закрепление кварталов
- **Офлайн** — Service Worker кеширует всё необходимое, ввод работает без интернета
- **Защита** — `helmet`, `express-rate-limit`, bcrypt

## 8. Два контура

| | Боевой | Демо |
|---|---|---|
| Ветка | `main` | `demo-five-modes` |
| Remote | GitHub → Render (autodeploy) | SourceCraft → VPS pm2 |
| URL | `pomoshnik-brigadira.onrender.com` | `demo.smart-assistantai.ru` |
| `DEMO_MODE` | `false` | `true` |
| Режимов | 3 (`rows_bushes`, `rows_only`, `hours`) | 5 (+`hectares`, `kilometers`) |
| Вкладка «Выполнение» | нет | есть |
| Инвентарь | `inventory.json` реального предприятия | демо-данные в памяти + БД |
| Сессии | постоянные (JWT) | временные (24 ч, без регистрации) |

Боевой и демо — два git-worktree **одного** локального `.git`.

## 9. Переменные среды (`.env`)

| Переменная | Обязательна | Описание |
|---|---|---|
| `DATABASE_URL` | да | Строка подключения к Postgres (`postgres://user:pass@host/db`) |
| `JWT_SECRET` | да | Секрет для подписи токенов, ≥ 32 случайных символа |
| `DEMO_MODE` | да | `true` для демо-контура, `false` для реального |
| `PORT` | нет | Порт сервера (по умолчанию 3000) |

Бренд (`BRAND_NAME`, `BRAND_LOGO`, `CONTACT_PHONE`) сейчас захардкожен в `config.js` — при развёртывании у клиента правится вручную (перевод в env — в чек-листе «что доделать», см. паспорт развёртывания).
