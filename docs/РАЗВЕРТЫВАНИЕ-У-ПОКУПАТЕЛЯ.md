# Развёртывание у покупателя

> Пошаговая инструкция: от пустого сервера до рабочего приложения с данными клиента.
> Читать вместе с «Паспортом проекта» (ПАСПОРТ-ПРОЕКТА.md).

---

## Что взять у покупателя до начала

- [ ] Excel-таблица инвентаря: предприятия, кварталы, клетки, ряды, кусты, гектары
- [ ] Название предприятия (для брендинга приложения)
- [ ] Контактный телефон (отображается в приложении)
- [ ] Список бригадиров: имя + логин (придумывает клиент или мы)
- [ ] Какие виды работ нужны (из списка в §6 паспорта, или новые)
- [ ] Нужна ли привязка кварталов к бригадирам (каждый видит только свои)

---

## Шаг 1. Сервер

Нужен VPS (Linux) с:
- Node.js ≥ 18
- PostgreSQL ≥ 14
- pm2 (`npm i -g pm2`)
- nginx + SSL-сертификат (Let's Encrypt)
- Домен клиента, направленный на IP сервера

Проверка готовности:
```bash
node -v        # ≥ 18
psql --version # ≥ 14
pm2 -v
```

---

## Шаг 2. Код

Берём за основу **демо-репо** (`demo-five-modes`) — в нём самый полный набор функций.

```bash
git clone <демо-репо> /opt/pomoshnik-<клиент>
cd /opt/pomoshnik-<клиент>
npm install --omit=dev
```

> Демо-репо приватное, доступ по SSH-ключу. Убедись, что ключ добавлен на сервере.

**Важно:** до деплоя нужно выполнить пункты из раздела «Что доделать в коде» ниже — без этого DEMO_MODE=false отключает расширенные функции.

---

## Шаг 3. База данных

```bash
# Создать пользователя и базу
sudo -u postgres psql
CREATE USER pomoshnik_<клиент> WITH PASSWORD 'сильный_пароль';
CREATE DATABASE pomoshnik_<клиент> OWNER pomoshnik_<клиент>;
\q
```

Строка подключения:
```
postgres://pomoshnik_<клиент>:пароль@localhost/pomoshnik_<клиент>
```

Таблицы создаются автоматически при первом запуске (`ensureTables` в `server.js`). Миграции вручную не нужны.

---

## Шаг 4. Инвентарь клиента → `inventory.json`

1. Взять Excel клиента.
2. Заполнить `parse_config.json` (соответствие колонок листам Excel).
3. Запустить парсер: `node server/parser.js` — он создаст `inventory.json` в корне.
4. Проверить: открыть `inventory.json`, убедиться что кварталы/клетки/ряды на месте.

`inventory.json` — gitignored, не попадает в репозиторий. Хранится только на сервере клиента.

---

## Шаг 5. Конфиг: `.env`

Создать файл `.env` в корне проекта:

```env
DATABASE_URL=postgres://pomoshnik_<клиент>:пароль@localhost/pomoshnik_<клиент>
JWT_SECRET=<минимум 32 случайных символа>
DEMO_MODE=false
PORT=3000
BRAND_NAME=Название предприятия клиента
BRAND_LOGO=🍇
CONTACT_PHONE=+7...
MEASURE_MODES=rows_bushes,rows_only,hours
```

Генерация JWT_SECRET:
```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

---

## Шаг 6. Режимы измерения

В `server/config.js` выбрать нужные режимы для этого клиента:

```js
// Пример для виноградаря без механизации:
const MEASURE_MODES = ['rows_bushes', 'rows_only', 'hours'];

// Пример с механизацией:
const MEASURE_MODES = ['rows_bushes', 'rows_only', 'hours', 'hectares'];
```

Полный список режимов — в §6 паспорта проекта.

---

## Шаг 7. Аккаунты бригадиров

После запуска (Шаг 8) создать аккаунты через API:

```bash
# Создать бригадира
curl -X POST http://localhost:3000/api/brigadiers \
  -H "Content-Type: application/json" \
  -d '{"login":"иванов","password":"пароль8+","name":"Иванов И.И."}'
```

Если нужна привязка кварталов — см. API `/api/brigadiers/:id/quarters`.  
Пароль ≥ 8 символов (проверяется на сервере).

---

## Шаг 8. Запуск и проверка

```bash
# Запустить через pm2
pm2 start server/server.js --name pomoshnik-<клиент> --env production
pm2 save
pm2 startup   # чтобы стартовало после перезагрузки сервера

# Проверить здоровье
curl http://localhost:3000/health   # должен вернуть {"ok":true}
```

Проверка через браузер (https://домен-клиента):
- [ ] Открывается страница входа
- [ ] Вход с аккаунтом бригадира работает
- [ ] Виды работ и кварталы подтянулись из инвентаря
- [ ] Тестовый ввод сохраняется (журнал показывает запись)
- [ ] Контроль рядов: попробовать ввести один ряд дважды — должна быть ошибка

---

## Шаг 9. Передача покупателю

1. Открыть приложение на телефоне клиента.
2. «Добавить на экран» (PWA) — браузер предложит сам, или через меню браузера.
3. Разослать бригадирам ссылку на домен + их логины/пароли (шаблон SMS есть в памяти проекта).
4. Показать: ввод работы, журнал, контроль рядов.

## Статус готовности к коммерческому деплою

- [x] **Расширенные режимы измерения** — управляются через `MEASURE_MODES` в `.env` (см. Шаг 5 и Шаг 6). Набор выбирается под каждого клиента независимо от `DEMO_MODE`.
- [x] **Вкладка «Выполнение» (га)** — работает в реальном режиме (`DEMO_MODE=false`). Показывает сделано/осталось по видам работ и кварталам. Требует `hectares` в `inventory.json`.
- [x] **Бренд через env** — `BRAND_NAME`, `BRAND_LOGO`, `CONTACT_PHONE` читаются из `.env` (см. Шаг 5).
- [~] **Демо-таблицы в реальном режиме** — создаются, но остаются пустыми и работе не мешают. При желании можно убрать позже; на функциональность не влияет.
